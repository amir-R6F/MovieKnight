# LANWatch — پخش هم‌زمان ویدیو در شبکه محلی

LANWatch چند کامپیوتر ویندوزی را طوری هم‌زمان می‌کند که **یک ویدیو** را با هم تماشا کنید.
این برنامه تصویر را ارسال نمی‌کند (مثل AnyDesk نیست)؛ فقط وضعیت پخش (پخش/توقف/جابه‌جایی)
را با پیام‌های کوچک JSON بین کامپیوترها هم‌سان می‌کند. هر کس **فایل ویدیوی خودش** را روی
کامپیوتر خودش با پخش‌کننده‌ی محلی `mpv` باز می‌کند و همه با هم پخش می‌شوند.

- یکی از کامپیوترها **میزبان (Host)** است و سرور WebSocket را اجرا می‌کند.
- بقیه **مهمان (Client)** هستند و به میزبان وصل می‌شوند.
- هر کسی هر دکمه‌ای بزند (پخش، توقف، جابه‌جایی زمان)، همه‌ی کامپیوترها همان کار را انجام می‌دهند.
- دکمه‌ی **Resync** همه را به موقعیت فعلی میزبان برمی‌گرداند (وقتی کسی عقب افتاد).
- شمارش معکوس **۳-۲-۱** قبل از پخش، شروع را برای همه دقیقاً هم‌زمان می‌کند.
- میزبان‌ها روی شبکه **خودکار پیدا می‌شوند** (mDNS)؛ وارد کردن IP دستی هم همیشه کار می‌کند.
- نه سرور بیرونی، نه دیتابیس، نه حساب کاربری، نه پرداخت. همه‌چیز محلی است.

---

## ۱) پیش‌نیازها (روی هر کامپیوتر)

1. **ویندوز ۱۰ یا ۱۱** (بدون نیاز به دسترسی Administrator)
2. **پایتون ۳.۱۱ یا بالاتر**
3. **پخش‌کننده mpv** (نسخه ۰.۳۳ یا بالاتر)
4. **همان فایل ویدیو** روی هر کامپیوتر (بهتر است دقیقاً یک فایل باشد؛ طول ویدیو باید یکی باشد)
5. برای پیدا شدن خودکار میزبان‌ها، هر دو کامپیوتر باید در **همان شبکه** باشند و شبکه اجازه‌ی
   multicast بدهد (بیشتر شبکه‌های خانگی می‌دهند؛ اگر نداد، IP را دستی وارد کنید).

### نصب پایتون

1. از <https://www.python.org/downloads/windows/> نسخه ۳.۱۲ را دانلود کنید.
2. در اولین صفحه‌ی نصب، تیک **«Add python.exe to PATH»** را بزنید (مهم است).
3. `Install Now` را بزنید و بعد از پایان، پنجره‌ی `cmd` را باز کنید و این را امتحان کنید:

   ```bat
   py -3 --version
   ```

   باید چیزی مثل `Python 3.12.x` نشان دهد.

### نصب mpv

راحت‌ترین راه با `winget` (در ویندوز ۱۰/۱۱ معمولاً موجود است):

```bat
winget install mpv
```

یا به‌صورت دستی:

1. از <https://mpv.io/installation/> یکی از بیلدهای ویندوز (مثلاً shinchiro) را دانلود کنید.
2. فایل ZIP را در مسیری مثل `C:\mpv\` باز کنید تا `C:\mpv\mpv.exe` به دست آید.
3. یا پوشه‌ی `C:\mpv` را به `PATH` اضافه کنید، یا فایل `mpv.exe` را داخل پوشه‌ی `lanwatch` بگذارید،
   یا مسیر کامل را در متغیر محیطی `LANWATCH_MPV` بنویسید:

   ```bat
   set LANWATCH_MPV=C:\mpv\mpv.exe
   ```

برای آزمایش، در `cmd` بنویسید `mpv --version`؛ باید نسخه را نشان دهد.
اگر mpv پیدا نشود، برنامه باز هم اجرا می‌شود ولی پیام می‌دهد که پخش‌کننده در دسترس نیست
(در آن حالت دکمه‌ی «Open File in mpv» فایل را در mpv بیرونی باز می‌کند، اما هم‌زمان‌سازی نخواهد بود).

## ۲) نصب خود برنامه

پوشه‌ی پروژه را روی کامپیوتر کپی کنید. سپس روی **`run.bat`** (در ریشه‌ی همان پوشه) دوبار کلیک کنید.

بار اول، `run.bat` به‌طور خودکار:

1. یک محیط مجازی `.venv` می‌سازد،
2. کتابخانه‌های لازم را از `lanwatch\requirements.txt` نصب می‌کند
   (`websockets`، `python-mpv-jsonipc`، `customtkinter`، `zeroconf`),
3. برنامه را اجرا می‌کند.

اجرای دستی (اگر ترجیح می‌دهید از `cmd` استفاده کنید، از ریشه‌ی پوشه‌ی پروژه):

```bat
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r lanwatch\requirements.txt
.venv\Scripts\python.exe lanwatch\main.py
```

## ۳) شروع میزبانی (روی کامپیوتر اول)

1. برنامه را اجرا کنید. بالای پنجره **«Host Session»** را انتخاب کنید.
2. آدرس **LAN IP** (مثلاً `192.168.1.20`) و در صورت وجود اینترنت، **Public IP** نمایش داده می‌شود.
3. اگر پورت پیش‌فرض `8765` مشکلی داشت، عدد دیگری وارد کنید (باید روی همه‌ی کامپیوترها یکی باشد).
4. دکمه‌ی **Start Hosting** را بزنید.
5. ویندوز ممکن است پنجره‌ی Windows Firewall نشان دهد؛ **Allow access** را بزنید تا کامپیوترهای
   دیگر شبکه بتوانند وصل شوند. (اگر رد کردید، بعداً از `Windows Defender Firewall → Allow an app`
   می‌توانید اجازه بدهید.)
6. دکمه‌ی **Open Video** را بزنید و فایل ویدیوی خودتان را انتخاب کنید.

> نکته: میزبان هم مثل بقیه، ویدیوی محلی خودش را پخش می‌کند و همان قوانین هم‌زمان‌سازی برایش اجرا می‌شود.
> هنگام Start Hosting، برنامه خودش را با نام
> `LANWatch on <نام کامپیوتر> (<نام نمایشی>)` روی شبکه معرفی می‌کند تا مهمان‌ها در لیست ببینند.
> اگر شبکه multicast را مسدود کرده باشد، فقط یک پیام اطلاع‌رسانی می‌بینید و میزبانی مثل قبل
> با IP دستی کار می‌کند.

## ۴) اتصال از کامپیوتر دوم (و بقیه)

1. در همان شبکه (یا همان Tailscale) برنامه را اجرا کنید.
2. بالای پنجره **«Join Session»** را انتخاب کنید.
3. ساده‌ترین راه: در بخش **«Discovered hosts»** یکی از میزبان‌های پیدا‌شده را انتخاب کنید؛
   فیلدهای IP و پورت خودشان پر می‌شوند. دکمه‌ی **Refresh** لیست را از نو جست‌وجو می‌کند.
   - هر میزبان به شکل `نام نمایشی — IP:پورت` نشان داده می‌شود.
   - اگر میزبانی خاموش شود، معمولاً در چند ثانیه از لیست حذف می‌شود.
   - اگر لیست خالی ماند (شبکه multicast را مسدود کرده، یا هر دو در دو شبکه‌ی متفاوت هستند)،
     IP را دستی وارد کنید؛ این روش همیشه کار می‌کند.
4. در صورت نیاز، **Host IP** و **Port** را دستی پر کنید و **Display name** را بنویسید.
5. **Connect** را بزنید. در لیست «Peers» باید میزبان و بقیه را ببینید (نقطه‌ی سبز = متصل).
6. **Open Video** را بزنید و **همان ویدیو** را باز کنید.

اگر هنگام اتصال، هنوز ویدیو باز نکرده باشید هم مشکلی نیست: به‌محض باز کردن فایل،
پخش‌کننده به همان جایی می‌رود که بقیه هستند (حالت پخش/توقف و زمان دقیق).

## ۵) کنترل‌ها و کلیدهای میان‌بر

| کنترل | کار |
|---|---|
| **Play / Pause** | پخش یا توقف هم‌زمان همه (با شمارش معکوس، اگر روشن باشد) |
| **Stop** | توقف و برگشت به زمان صفر روی همه |
| **Resync** | همه را به موقعیت و وضعیت فعلی میزبان می‌برد |
| **Seek slider** | جابه‌جایی زمان؛ همه با هم جابه‌جا می‌شوند |
| **Open Video** | باز کردن فایل ویدیوی محلی توسط mpv داخلی |
| **Open File in mpv** | باز کردن فایل در mpv بیرونی (وقتی IPC کار نمی‌کند) |

| کلید | کار |
|---|---|
| `Space` | پخش/توقف |
| `S` | توقف (Stop) |
| `R` | همگام‌سازی اجباری (Resync) |
| `←` / `→` | ۱۰ ثانیه عقب/جلو |

در نوار پایین، **موقعیت فعلی** و برای مهمان‌ها **اختلاف ساعت (clock offset)** و **RTT** نمایش
داده می‌شود؛ این‌ها برای هم‌زمان‌سازی دقیق‌ترند و مقدار کم (چند میلی‌ثانیه) طبیعی است.

## ۶) همگام‌سازی اجباری (Resync)

گاهی صدا و تصویرِ یک کامپیوتر چند ثانیه عقب می‌افتد (کمبود CPU، بافر شبکه، یا کسی در mpv
دستی جابه‌جا کرده). دکمه‌ی **Resync** (یا کلید `R`) این را درست می‌کند:

- روی **هر کامپیوتری** (میزبان یا مهمان) بزنید.
- برنده همیشه **میزبان** است: میزبان موقعیت واقعی پخش‌کننده‌ی خودش و وضعیت پخش/توقف را می‌خواند
  و به همه اعلام می‌کند.
- همه بلافاصله به همان زمان می‌پرند و اگر میزبان در حال پخش است، پخش ادامه پیدا می‌کند؛
  اگر میزبان متوقف است، همه متوقف می‌مانند.
- شمارش معکوس برای Resync اجرا **نمی‌شود**؛ باید فوری باشد.
- تا حدود ۲ ثانیه در نوار وضعیت «Resyncing...» دیده می‌شود.

> Resync فقط وقتی معنی دارد که یک نشست فعال باشد (میزبان در حال Hosting یا مهمان متصل).
> اگر هیچ نشستی نباشد، پیام راهنما نشان داده می‌شود.

## ۷) شمارش معکوس ۳-۲-۱ قبل از پخش

با روشن بودن گزینه‌ی **«Countdown before play»** (پیش‌فرض: روشن)، هر بار کسی Play بزند:

1. همه‌ی کامپیوترها روی همان فریم متوقف می‌شوند.
2. یک کارت بزرگ وسط پنجره ظاهر می‌شود: **۳** → **۲** → **۱** → **GO**.
3. در لحظه‌ی GO، همه با هم پخش می‌کنند و کارت محو می‌شود.

جزئیات مهم:

- شمارش معکوس بر اساس ساعت میزبان محاسبه می‌شود؛ بنابراین کندی شبکه باعث می‌شود کارتِ بعضی‌ها
  دیرتر ظاهر شود ولی **لحظه‌ی شروع برای همه یکی است**.
- **تنظیم کسی که Play را زده، برای همان پخش تعیین‌کننده است**: اگر شمارش معکوس او خاموش باشد،
  همان پیام با «شروع فوری» فرستاده می‌شود و همه فوری پخش می‌کنند. برعکسش هم همین‌طور.
- با **Pause**، کلید `Space`، **Stop**، **Seek**، **Resync** یا کلیک روی خود کارتِ شمارش،
  شمارش بلافاصله لغو می‌شود.
- اگر در حال پخش باشید و دوباره Play بزنید، هیچ کاری نمی‌شود (نه پرش، نه شمارش).
- مدت شمارش در `lanwatch/config.py` با `PLAY_COUNTDOWN_SECONDS` قابل تغییر است.
- انتخاب شما ذخیره می‌شود در:
  `%APPDATA%\LANWatch\settings.json` (کلید `countdown_before_play`).
  این فایل خودکار ساخته می‌شود و خراب شدنش برنامه را از کار نمی‌اندازد.

## ۸) پیدا کردن خودکار میزبان (mDNS)

میزبان هنگام Start Hosting، سرویس `_lanwatch._tcp.local.` را روی شبکه معرفی می‌کند
(با نام نمایشی، پورت و نسخه). مهمان‌ها در حالت Join همین سرویس را جست‌وجو می‌کنند.

- لیست **Discovered hosts** فقط در حالت Join فعال است.
- **Refresh** لیست را پاک و دوباره جست‌وجو می‌کند.
- انتخاب یک مورد، فیلد IP و پورت را پر می‌کند (بعدش Connect را بزنید).
- اگر میزبان Stop Hosting بزند یا برنامه بسته شود، سرویس پاک می‌شود و از لیست حذف می‌شود.

محدودیت‌ها:

- mDNS روی **UDP 5353** و به‌صورت multicast کار می‌کند؛ بعضی شبکه‌ها (Wi-Fi عمومی، هتل،
  شبکه‌های با «AP isolation» و برخی VPNها) آن را مسدود می‌کنند. در این حالت لیست خالی می‌ماند
  و باید IP را دستی وارد کنید — همه‌ی قابلیت‌های دیگر بدون مشکل کار می‌کنند.
- اگر `zeroconf` نصب نباشد یا شبکه آدرس غیر-loopback نداشته باشد، بخش جست‌وجو مخفی می‌شود
  و فقط ورود دستی IP می‌ماند (برنامه کرش نمی‌کند).
- برای Tailscale: آدرس `100.x.y.z` ممکن است در لیست پیدا نشود؛ آن را دستی وارد کنید.

## ۹) استفاده از اینترنت با Tailscale (اختیاری)

اگر هر دو نفر Tailscale ندارید، فقط در همان Wi-Fi/LAN می‌توانید وصل شوید. برای تماشای مشترک
از راه دور و **بدون باز کردن پورت روی مودم**:

1. روی هر دو کامپیوتر Tailscale را از <https://tailscale.com/download/windows> نصب کنید.
2. با **همان حساب کاربری** (یا با دعوت به همان شبکه) وارد شوید.
3. در Tailscale، آدرس `100.x.y.z` هر کامپیوتر را ببینید.
4. روی میزبان: `Start Hosting` را بزنید.
5. روی مهمان: در **Host IP** همان آدرس `100.x.y.z` میزبان را وارد کنید و `Connect` بزنید.

Tailscale رایگان است و کار کردن با آن برای این برنامه کافی است. در این حالت لازم نیست پورتی
روی مودم باز کنید.

## ۱۰) رفع اشکال

| مشکل | راه‌حل |
|---|---|
| «mpv is not available» | mpv نصب نیست یا در `PATH` نیست. `winget install mpv` یا مسیر `mpv.exe` را در `LANWATCH_MPV` بگذارید. |
| اتصال برقرار نمی‌شود | IP درست است؟ هر دو در یک شبکه؟ فایروال ویندوز روی میزبان اجازه داده؟ همان پورت وارد شده؟ |
| لیست Discovered hosts خالی است | شبکه multicast را مسدود کرده یا دو دستگاه در یک subnet نیستند. `Refresh` بزنید یا IP را دستی وارد کنید. |
| میزبان پیدا می‌شود ولی Connect کار نمی‌کند | فایروال ویندوز پورت برنامه (پیش‌فرض ۸۷۶۵) را مسدود کرده؛ همان پورت را باز/اجازه دهید. |
| «port is already in use» | پورت ۸۷۶۵ اشغال است؛ پورت دیگری (مثلاً ۸۷۶۶) روی میزبان و مهمان‌ها بگذارید. |
| Resync اثری ندارد | باید یک نشست فعال باشد (Hosting یا متصل). اگر مهمان هستید و اتصال قطع شده، اول Reconnect کنید. |
| شمارش معکوس نمایش داده نمی‌شود | تیک «Countdown before play» را ببینید. یادتان باشد تنظیم **کسی که Play می‌زند** تعیین‌کننده است. |
| هشدار «video may be a different version» | طول ویدیوها بیش از ۱ ثانیه فرق دارد: نسخه‌ی فایل ویدیو روی همه باید یکی باشد. |
| صدا/تصویر کمی عقب‌تر است | اگر اختلاف بیش از ۰٫۴ ثانیه شود برنامه خودش تصحیح می‌کند؛ در موارد شدید `Resync` بزنید. |
| مهمان قطع شد | اگر میزبان بسته شود، مهمان‌ها پیام «Disconnected from host» می‌بینند، پخش متوقف می‌شود و دکمه به **Reconnect** تبدیل می‌شود. |
| پخش در mpv بیرونی باز می‌شود ولی هم‌زمان نیست | آن دکمه فقط «اضطراری» است. باید از Open Video (mpv داخلی با IPC) استفاده کنید. |

```
LANWatch/
├── run.bat              # ساخت محیط مجازی و اجرای برنامه (ویندوز)

├── tests/
│   ├── conftest.py
│   ├── helpers.py
│   ├── test_protocol.py
│   ├── test_player.py
│   ├── test_sync_integration.py

    ├── main.py          # نقطه ورود: راه‌اندازی mpv، حلقه asyncio و پنجره

    ├── host.py          # سرور WebSocket میزبان و وضعیت مرجع پخش
    ├── client.py        # کلاینت WebSocket
    ├── protocol.py      # پیام‌ها، سریال‌سازی JSON، حذف اکو

    └── requirements.txt
```

.venv\Scripts\python.exe -m pytest -v

راهنمای کامل (اجرای انتخابی، پوشش کد، فیکسچرها و مارکرها) در فایل
[TESTING.md](TESTING.md) آمده است.

- تست‌های شبکه‌ای با WebSocket واقعی روی `127.0.0.1` و پخش‌کننده‌ی ساختگی اجرا می‌شوند؛
  به mpv یا فایل ویدیو نیاز ندارند.
- تست‌های mDNS اگر zeroconf یا رابط شبکه‌ی مناسب نباشد `skip` می‌شوند.
- تست‌های GUI به محیط گرافیکی (Tk) نیاز دارند؛ روی سیستم بدون نمایشگر `skip` می‌شوند.

## ۱۳) محدودیت‌ها

- ویدیو **منتقل نمی‌شود**؛ هر کامپیوتر باید فایل خودش را داشته باشد.
- برای هم‌زمانی بهتر، فایل‌ها باید یکسان باشند (اختلاف طول بیش از ۱ ثانیه هشدار می‌دهد).
- mpv داخلی برای هر برنامه یک named pipe جدا (`lanwatch_mpv_<pid>`) می‌سازد؛ به همین دلیل می‌توانید
  روی یک کامپیوتر دو نمونه (میزبان + مهمان) برای آزمایش اجرا کنید.
- پیدا کردن خودکار میزبان به multicast شبکه وابسته است؛ ورود دستی IP همیشه در دسترس است.
- برنامه برای شبکه‌ی محلی طراحی شده است؛ روی اینترنت فقط با Tailscale (یا VPN مشابه) توصیه می‌شود.
